# Cryomagnetics LM-510 liquid helium level meter (`lm510`)

`generalmeasurements/devices/lm510.py`. Readable: one channel's level, in the
meter's units (`in`, `cm` or `%`).

**Status:** written from the LM-510 manual and the legacy
`LabviewLegacy/HeliumMonitor.vi`. **Not verified on hardware.** The lab meter
is at `TCPIP0::192.168.1.51::4266::SOCKET`, a Digi serial-to-LAN adapter. The
adapter accepts connections, but the meter has never answered (`*IDN?` times
out with LF, CR or CR LF line endings). That points to the serial side: is the
meter on, is the cable connected, does the baud rate match, and is the meter's
remote interface set to RS-232?

## Station config

```toml
[devices.helium]
driver = "lm510"
resource = "TCPIP0::192.168.1.51::4266::SOCKET"
channel = 1          # 1 or 2
units = "in"         # must match the meter's UNITS setting; configure() checks
echo = true          # the meter repeats each command on RS-232; harmless if it doesn't
```

## Commands used

| Purpose | Command | Notes |
| --- | --- | --- |
| identify | `*IDN?` | must contain `LM-510` |
| level | `MEAS? <ch>` | last measured level, e.g. `23.4 in`; does **not** start a measurement |
| measure now | `MEAS <ch>` | heats the sensor, boils some helium; GUI button only |
| mode | `MODE?`, `MODE S` / `MODE C` | Sample/Hold or Continuous |
| interval | `INTVL?`, `INTVL hh:mm:ss` | Sample/Hold measurement interval |
| units, sensor | `UNITS?`, `LNGTH?` | |
| alarms | `LOW?`, `HIGH?` | shown on the dewar gauge; "time to low" uses `LOW?` |

`MODE`, `INTVL`, `UNITS`, `LOW`, `HIGH` and `LNGTH` act on the channel
selected on the meter. The driver never changes the selected channel.

## Quirks and known gaps

- **Single client.** The Digi port takes one TCP client. A half-closed
  connection blocks new ones for a while (seen during the first probes).
  Keep one session open; don't poll by reconnecting.
- **Echo.** On RS-232 the meter echoes commands. The transport skips a reply
  line that equals the command, and after a write it waits up to 0.5 s for the
  echo.
- Unverified on hardware: the exact replies to `MODE?`, `INTVL?` and the alarm
  queries.
